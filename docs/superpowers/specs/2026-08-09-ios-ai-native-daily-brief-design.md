# iOS AI-Native 每日简报与工作台设计

日期：2026-08-09
状态：待用户复核书面规格

## 1. 背景与目标

当前 iOS 首页只在右上角显示一个“AI”文字按钮，AI 能力被隐藏；点击后出现的工作台以纵向按钮、空输入框和大块纯文本输出为主，像调试表单，不像产品主能力。Web 版通过持续可见的 Agent Copilot 区域、目标输入与任务上下文，更清楚地表达了 AI-native 定位。

本次选择“方案 A：AI 每日简报”。目标不是照搬 Web 三栏布局，而是在移动端建立一条清晰路径：

1. 首页先展示 AI 已经基于任务上下文得出的判断。
2. 用户可直接从简报进入“今日计划 / 拆解目标 / 复盘”三种工作模式。
3. AI 结果以可选择、可导入的任务结构呈现，不再只输出一段文本。
4. AI 永远不会在未确认时修改、删除或重排用户任务。

## 2. 已确认的产品决策

- 首页采用 AI 每日简报主卡，位置高于“执行态势”和“今日计划”。
- 每个自然日首次进入首页时自动生成一次简报。
- 任务、截止时间或执行状态变化后，只把简报标记为“建议可更新”，不自动重复调用 AI。
- 用户可手动刷新简报。
- 托管额度和自带 API Key 都使用同一套界面；模型配置仍留在设置页。
- AI 工作台采用连续画布：模式、上下文、输入、结构化结果与应用动作处于同一路径。
- 首页简报和工作台共享同一份任务上下文与刷新状态。

## 3. 首页信息架构

首页从上到下排列：

1. 导航标题“今日”，右侧入口由模糊的“AI”改为“AI 简报”，并配系统 SF Symbol。
2. AI 每日简报卡。
3. 执行态势。
4. 今日计划。

### 3.1 AI 每日简报卡

卡片包含：

- 标签：`今日 AI 简报`。
- 状态：更新时间；上下文变化后显示`建议可更新`。
- 主结论：一句明确、可行动的优先级判断。
- 补充说明：说明今天应关注的结果或风险。
- 判断依据：例如进行中任务数、临近截止数和健康分，不展示模型内部推理过程。
- 快捷动作：`生成计划`、`帮我取舍`、`拆解目标`。

点击卡片主体或导航入口，默认打开“今日计划”模式。点击快捷动作时，直接打开对应模式，并预填与动作相符的提示。

### 3.2 首页状态

- 首次生成中：卡片保留稳定高度，显示短文案和轻量加载状态，减少布局跳动。
- 已生成：展示结论、说明、依据和快捷动作。
- 建议可更新：保留旧内容，显示更新状态；用户仍可进入工作台。
- 离线或服务失败：展示本地规划器生成的简报，并明确标记`本地建议`，不出现空白卡。
- 额度耗尽：保留最近一次简报；刷新失败时显示内联提示，并提供前往设置或订阅的入口。

## 4. AI 工作台

工作台继续以系统 Sheet 呈现，使用可见拖拽指示器和大尺寸高度。顶部不再重复大号“AI 工作台”标题，而是显示：

- 小标签：`AI 计划助手`。
- 标题：`把想法变成下一步`。
- 服务状态：`托管 AI · DeepSeek`或当前自定义服务商，以及额度/连接状态。
- 完成按钮。

### 4.1 模式切换

顶部使用三段式模式切换：

- 今日计划：从现有任务中选择 3–5 项，给出顺序与时间建议。
- 拆解目标：把目标拆成可导入的小任务。
- 复盘：总结进展、风险和下一步，不默认生成待办。

模式切换会改变输入提示、快捷提示和结果布局，但保留用户尚未提交的输入。切换模式不会自动发起请求。

### 4.2 上下文说明

在输入区域上方显示一条简短上下文说明，例如：

`已读取 24 项任务、3 个截止时间与当前健康分；不会自动修改任务。`

这条说明用于建立信任，只说明使用了哪些数据，不展示模型内部推理内容。

### 4.3 输入区域

输入区域包括：

- 随模式变化的问题标题。
- 支持多行的自然语言输入。
- 2–3 个可点选的提示胶囊，例如`只排 3 件事`、`保留缓冲时间`。
- 单一主按钮，例如`生成今日建议`。

移除现有三个纵向按钮。模式选择负责表达意图，主按钮负责执行。

### 4.4 结构化结果

今日计划和拆解目标的结果由以下内容组成：

- 一段简短建议说明。
- 3–8 条结构化建议任务。
- 每条任务包含标题，可选的时长、优先级、截止时间与一句理由。
- 每条任务可独立选择，默认全选。
- 底部固定主动作：`加入今日计划（N）`或`加入待办（N）`。
- 次动作：`重新生成`。

复盘模式展示三段结构：进展概览、下一步建议、推荐给 AI 的下一条提示；不显示任务选择框，除非结果中明确包含可导入建议。

导入前检查现有未归档任务标题，避免重复创建。所有导入任务通过现有 `TodoViewModel.captureNaturalLanguage` 进入统一数据与提醒流程。

## 5. 数据模型与模块边界

新增以下独立模型，避免继续把全部 AI 状态堆入单一字符串：

### 5.1 `AIDailyBrief`

- `summary`：主结论。
- `detail`：补充说明。
- `evidence`：用于界面展示的上下文依据数组。
- `generatedAt`：生成时间。
- `source`：托管 AI、自带 Key 或本地规划器。
- `contextFingerprint`：生成时的任务上下文指纹。

模型遵循 `Codable` 与 `Equatable`，支持缓存和单元测试。

### 5.2 `AIWorkbenchMode`

枚举值：`todayPlan`、`breakdown`、`review`。每种模式负责提供标题、输入提示、快捷提示和主按钮文案。

### 5.3 `AISuggestedTask`

- 稳定 ID。
- 标题。
- 可选时长、优先级和截止时间。
- 简短理由。
- 是否被用户选中由 ViewModel 管理，不写入模型持久层。

### 5.4 `AIBriefingViewModel`

独立负责：

- 每日首次生成策略。
- 上下文指纹计算与“建议可更新”状态。
- 简报缓存。
- 工作台模式、输入、加载、结果和错误状态。
- 选择与导入建议任务。

现有 `AIViewModel` 继续负责设置页的服务商、模型与 API Key 配置。两者通过 `OpenAIService` 的持久配置读取当前 AI 连接方式，避免把界面配置复制到新 ViewModel。

## 6. 数据流

### 6.1 每日简报

1. 首页出现时构建任务上下文快照。
2. 读取当天缓存。
3. 若当天没有缓存，自动调用 `AIService.dailyBrief`。
4. 若缓存存在，立即显示缓存；比较上下文指纹。
5. 指纹不一致时标记`建议可更新`，但不自动调用。
6. 用户点击刷新后重新生成并覆盖当天缓存。

上下文指纹只包含会影响建议的稳定字段：任务 ID、标题、状态、优先级、预计时长、到期时间、归档状态和健康分。排序后计算，避免列表顺序造成误刷新。

### 6.2 工作台

1. 首页入口传入目标模式与可选预填提示。
2. ViewModel 根据模式构造上下文和请求。
3. `AIService` 返回结构化建议。
4. 若远端结果无法解析，回退到本地结构化规划器，不展示原始 JSON 或空白输出。
5. 用户调整选择后点击导入。
6. ViewModel 去重并逐项调用现有任务创建入口。
7. 导入成功后刷新首页任务、计划和简报更新状态。

## 7. AI 服务与降级

新增结构化服务入口：

- `AIService.dailyBrief(items:health:)`
- `AIService.workbench(mode:goal:items:health:)`

远端请求要求返回受控 JSON，客户端解码为 `AIDailyBrief` 或建议结果。遇到以下情况时使用本地规划器：

- 无自带 Key且托管服务不可用。
- 网络或服务商失败。
- 返回内容无法解码。

额度耗尽仍保留为显式业务错误，不静默伪装成远端结果；界面保留旧内容并给出恢复入口。日志不得记录 API Key、完整用户输入或完整任务正文。

## 8. 动效与无障碍

- 卡片首次出现使用轻微透明度与 8pt 位移，不使用大幅弹簧动画。
- 刷新结果使用内容淡入，不整体重排页面。
- 开启“减弱动态效果”后只保留短淡入。
- 所有按钮触控区域至少 44×44pt。
- AI 简报卡合并为清晰的可访问元素，读出更新时间、结论和是否可更新。
- 模式切换使用系统 Picker 语义。
- 加载、失败和导入成功通过可访问状态文本及公告表达，不能只依赖颜色或动画。
- Dynamic Type 下快捷动作可换行，结果任务改为纵向布局，不发生水平裁切。

## 9. 本地化

所有新文案提供中文和英文，包括：

- 简报标题、更新时间、可更新和本地建议状态。
- 三种模式名称与输入提示。
- 上下文说明。
- 生成、重新生成、导入与错误恢复动作。
- VoiceOver 标签和状态公告。

服务商名称和模型名称不翻译。

## 10. 测试与验收

### 10.1 单元测试

- 每日首次进入仅自动生成一次。
- 同一天已有缓存时不重复调用。
- 任务上下文改变后只标记可更新。
- 手动刷新更新缓存和指纹。
- 次日自动生成新简报。
- 无网络或解析失败时产生本地结构化结果。
- 额度耗尽保留旧简报并进入可恢复错误状态。
- 三种工作台模式生成正确的提示和结果类型。
- 建议任务选择、去重与导入正确。
- 中英文新增键完整。

### 10.2 界面验收

- 首屏无需点击即可看到 AI 判断和快捷动作。
- 顶部不再只有难理解的“AI”文字按钮。
- 工作台没有旧版大块空白输出框和三个纵向模式按钮。
- 结果可直接选择并加入今日计划或待办。
- 加载、空结果、失败、额度耗尽和本地降级均有明确状态。
- 最大 Dynamic Type、深色模式、Reduce Motion 与 VoiceOver 基本路径可用。

### 10.3 回归验证

- iOS 完整测试套件通过。
- Release 构建通过，Debug 专用入口仍被隔离。
- 真机完成构建、WiFi 安装与启动。
- 验证首次打开自动简报、任务变化后提示更新、手动刷新和建议任务导入。

## 11. 非目标

- 本轮不把 AI 做成跨 Tab 常驻输入坞。
- 本轮不把“伙伴”Tab 与 AI 工作台合并。
- 本轮不允许 AI 自动修改或删除任务。
- 本轮不新增后台定时 AI 请求或推送式 AI 建议。
- 本轮不重做设置页的服务商与模型配置。
