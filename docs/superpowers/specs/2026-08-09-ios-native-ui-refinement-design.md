# iOS 原生界面精修与核心交互升级 — 设计规格

日期：2026-08-09
状态：用户已确认设计，待实施计划

## 1. 背景

当前 iOS 真机通知链路已经验证可用，但几处产品表达仍不够完整：

- 设置页把通知授权状态呈现为操作按钮，缺少 App 内提醒总开关；测试通知也会出现在发行界面。
- AI 模型只能自由输入，常用模型缺少可发现的选择入口，不同服务商之间还会共用自定义配置。
- 伙伴页同时显示麦克风、文本框和发送按钮，没有形成微信式键盘/语音互斥模式，实时识别还会覆盖草稿。
- 首页导航标题和卡片标题重复显示“今日面板”，摘要卡片过多，首屏核心任务被下推。
- 动效分散在各页面，力度和节奏不统一，“减少动态效果”的覆盖也不完整。

本轮仅升级 iOS 原生 App。保留现有暖色品牌、SwiftUI 技术栈、任务业务逻辑、AI 额度规则和通知内容，不引入新的视觉资产或跨端改版。

## 2. 目标与成功标准

### 2.1 产品目标

1. 提醒通知成为用户可理解、可关闭、可恢复的 App 级能力。
2. 常用 AI 模型可以直接选择，同时保留自定义模型与自定义 OpenAI 兼容地址。
3. 伙伴输入采用图标化的键盘/语音模式切换，语音识别安全进入草稿而不自动发送。
4. 首页只保留一个清晰标题，首屏优先展示执行摘要和今日任务。
5. 建立统一、克制、支持无障碍设置的动效语言。

### 2.2 验收结果

- 普通尺寸 iPhone 首屏只有一个“今日”标题，并能看到第一条今日计划。
- Release 构建不出现测试通知或待发提醒数；Debug 构建保留诊断入口。
- 关闭提醒后，任务提醒全部取消且后续任务不会调度；重新开启只恢复仍有效的未来提醒。
- 每个 AI 服务商提供常用模型与“自定义…”；切换服务商不会串改模型配置。
- 伙伴页通过微信式语音波纹/键盘图标切换模式；录音不会覆盖已有草稿，也不会自动发送。
- iOS 测试全绿，模拟器完成视觉与交互检查，真机完成构建、安装、启动及关键路径复测。

## 3. 设计方向

采用已确认的方案 A：**原生克制**。

- 背景：暖白到极浅绿色，保持当前产品的温和感。
- 品牌色：珊瑚红用于主要行动；系统蓝用于选择、链接和当前状态；绿色用于成功。
- 卡片：16–18pt 连续圆角、细边框、轻阴影，不使用重玻璃、强渐变或大面积高饱和色。
- 层级：依靠系统字号、字重、间距和内容优先级形成，不再堆叠重复大标题。
- 控件：优先使用系统 `Toggle`、`Picker`、`Menu`、`TextField`、`Form` 和系统图标。
- 图标：语音/键盘切换使用与微信交互语义一致的 SF Symbols 近似图标，界面不显示模式文字；通过 VoiceOver 补全语义。

## 4. 页面信息架构

### 4.1 今日页

页面顺序：

1. 导航标题“今日”。
2. 紧凑执行摘要：完成率、当前进行数量、健康状态；会员/试用状态以轻量胶囊呈现。
3. 今日计划：作为首屏主内容，第一条任务必须尽早出现。

调整原则：

- 删除 `headerSection` 内重复的“今日面板”和副标题卡片。
- 原四宫格统计压缩为一张连续摘要，不让统计值抢占任务主体。
- “生成今日计划”保留为主要行动；“重新生成”和“AI 优化”收纳为次级菜单或紧凑次级按钮。
- 试用到期不在进入首页时自动弹付费墙；首页只显示轻量状态，用户点击受限能力或会员状态时再进入订阅页。

### 4.2 设置页

继续使用原生 `Form` 语义，统一为“标签在左、当前值或控件在右”的设置行。

提醒通知分区：

- 第一行：`Toggle`，标签为“提醒通知”。
- 第二行：只读系统权限状态，例如“系统通知：已允许/已关闭”；权限被拒绝时提供“前往系统设置”。
- `#if DEBUG` 内追加“发送测试通知”和“待发提醒数”。整个诊断 UI 及实现入口不进入 Release。

AI 设置分区：

- 服务商使用导航式 `Picker`。
- 模型使用导航式 `Picker` 或 `Menu`，列出该服务商常用模型和“自定义…”。
- 选择“自定义…”后才显示模型输入框。
- 仅自定义服务商显示 Base URL；预设服务商默认隐藏地址，避免普通用户误改。
- API Key 保持安全输入；托管免费额度未配置 Key 时明确显示“托管模式固定使用 DeepSeek 模型”。

### 4.3 伙伴页

输入条位于消息列表和底部 Tab Bar 之间，遵守安全区并避免遮挡最后一条消息。

键盘模式：

- 左侧为语音波纹圆形图标，点击切换到语音模式。
- 中间为多行文本输入。
- 右侧为发送按钮；空输入、AI 忙碌、录音结束处理中时禁用。

语音模式：

- 左侧变为键盘圆形图标，点击取消录音并返回键盘模式。
- 中间为大面积可点击录音区，不显示“按住说话”或模式文字。
- 空闲时点击一次开始录音；录音中再次点击结束。
- 录音中以颜色、波纹和触觉反馈表达状态；识别处理中切换为克制的静态进度反馈。
- 实时识别文本只在录音区临时预览，不直接写入正式草稿。

## 5. 核心交互与状态设计

### 5.1 提醒通知

通知包含两个独立状态：

- App 开关：用户是否希望 TodoNative 调度任务提醒。
- 系统授权：iOS 是否允许 App 展示通知。

有效状态为两者同时成立。App 开关使用持久化值，建议键名 `reminders_enabled`；首次升级保持兼容：系统已经授权的用户默认视为开启，系统未决定或拒绝的用户默认关闭。

#### 开启流程

1. 系统状态为 `.notDetermined`：请求权限。
2. 用户允许：保存 App 开关为开启，恢复有效提醒并刷新状态。
3. 用户拒绝：App 开关保持关闭，显示系统设置引导。
4. 系统已经允许：直接保存开启并恢复有效提醒。
5. 系统已经拒绝或受限：不开启，提供前往系统设置入口。

#### 关闭流程

1. 立即保存 App 开关为关闭。
2. 取消全部任务提醒。
3. 后续新增、编辑或自然语言解析出的到期任务不再调度。
4. Debug 待发数量刷新为零；测试通知不计入任务提醒统计。

#### 恢复规则

重新开启时只恢复同时满足以下条件的任务：

- 未完成。
- 未归档。
- 有到期时间。
- 到期时间仍晚于当前时间。

通知标识统一为 `task-reminder.<UUID>`。迁移期的取消逻辑同时清理旧的裸 UUID 标识，避免升级后残留重复提醒。所有创建、编辑、归档、完成与删除路径通过 `NotificationService` 的同一状态门控。

App 启动时只设置通知 delegate 和同步状态，不再无条件弹出系统授权请求。

### 5.2 AI 模型选择

数据模型扩展为：

```swift
struct AIModelOption: Identifiable, Equatable {
    let id: String
    let displayName: String
}

enum AIModelSelection: Equatable {
    case preset(String)
    case custom
}
```

每个 `AIProvider` 提供 `models` 和 `defaultModelID`。初始常用列表控制在 2–4 项。以下是基于仓库现有默认值的候选目录；实施时必须以各服务商官方文档核验仍可用的模型标识，不能把已下线模型固化到发行版：

- OpenAI：`gpt-5.1`、`gpt-5-mini`、`gpt-4.1-mini`。
- DeepSeek：`deepseek-v4-flash`、`deepseek-v4-pro`。
- Moonshot：`kimi-k2.6`、`kimi-k2.5`、`moonshot-v1-8k`。
- Zhipu GLM：`glm-5.2`、`glm-5.1`、`glm-4.5-flash`。
- Qwen：`qwen-plus`、`qwen-turbo`、`qwen-max`。
- Groq：保留当前默认模型，并提供服务已验证支持的 1–2 个补充预设。
- SiliconFlow：`deepseek-ai/DeepSeek-V3.2`、`Qwen/Qwen3.5-27B`、`Pro/zai-org/GLM-5`。
- Custom：只提供自定义模型和 Base URL。

模型与自定义输入按服务商独立保存：

- `ai_model_selection.<providerID>`
- `ai_custom_model.<providerID>`
- `ai_custom_base_url.<providerID>`，仅 Custom 必需

旧的全局 `ai_model` 和 `ai_base_url` 在首次读取时迁移到当前服务商的自定义配置，迁移成功后不重复执行。有效配置解析顺序为：当前服务商选择的预设 → 当前服务商自定义值 → 服务商默认值。

托管额度路径仍由 Worker 使用单一固定模型，本轮不扩大为多模型代理。实施前核验发现旧固定值 `deepseek-chat` 已在 2026-07-24 停用，因此 Worker、Web 提示和 iOS 托管请求必须同步迁移为 `deepseek-v4-flash`；UI 必须明确区分托管固定模型与用户 API Key 直连模型，避免配置假生效。

### 5.3 语音输入

录音状态机：

```text
idle → requestingPermission → recording → finalizing → idle
```

异常或用户取消可从任一非空闲状态回到 `idle`，且必须清理音频引擎、识别请求与回调。

交互规则：

- 第一次点击录音区：检查麦克风和语音识别权限，允许后开始录音。
- 第二次点击录音区：结束采集并进入 `finalizing`。
- 最终识别成功：把文本写入输入框，自动回到键盘模式，但不自动弹出键盘、不自动发送。
- 草稿为空时直接写入；已有草稿时用自然空格或换行追加，不覆盖原文。
- 最终结果为空时保留原草稿。
- 实时结果只更新临时 transcript，不修改 `buddy.input`。
- 录音过程中点击键盘图标：取消本次录音，恢复切换前草稿。
- 页面退出、App 进入后台、识别错误或权限变化：停止并清理录音，保留原草稿。
- AI 正在回复时不可开始新录音；已经开始的录音始终可以停止或取消。

权限错误分为麦克风和语音识别两类。被拒绝时显示准确文案，并提供前往系统设置的行动。

## 6. 视觉与动效规范

所有动效参数集中定义在 `AppTheme.Motion`，页面不再各自散落 magic number。

| 场景 | 标准动效 | 减少动态效果 |
|---|---|---|
| 按压反馈 | 0.10–0.12s ease-out，缩放至 0.98 | 无缩放 |
| 状态切换 | 0.12–0.15s 淡入淡出 | 0.12s 淡入淡出 |
| 数字更新 | 0.20–0.22s numeric transition | 直接更新 |
| 进度条 | 0.30–0.32s ease-in-out，无过冲 | 直接更新 |
| 列表插入 | 0.22–0.24s，淡入并上移 8pt | 0.12s 淡入 |
| 完成任务 | 勾选 0.18s，暖色闪光 0.22s，收起 0.24–0.28s | 0.12s 淡出 |
| 录音状态 | 克制呼吸波纹，约 0.9s 循环 | 静态高亮 |
| 系统页面 | 原生 sheet/navigation 转场 | 系统决定 |

约束：

- 删除所有滚动时反复触发的卡片 `onAppear` 入场动画。
- 任务移除不使用当前 `scale(0.85)` 的强烈缩小效果。
- 不使用弹跳明显的 spring；进度与数据变化不允许过冲。
- 动画只用于解释状态变化，不用于装饰静态页面。

## 7. 无障碍与本地化

- 所有可点击区域至少 44×44pt。
- 语音波纹、键盘、开始录音、停止录音、处理中提供独立 VoiceOver label/hint/value。
- 录音状态变化通过可访问性公告告知用户，但避免实时 transcript 高频播报。
- 执行进度提供百分比 `accessibilityValue`，不能只依赖颜色。
- 任务卡片中的完成、状态和归档应保持为独立操作，避免整卡点击语义冲突。
- 支持 Dynamic Type；较大字号下设置行允许垂直布局，输入条和今日摘要不能裁切。
- 使用现有主题 token 检查浅色和高对比度，不新增仅靠低对比细线表达状态的控件。项目当前强制 Light Mode，完整深色适配不计入本轮完成范围。
- 新增文案全部覆盖中英文；“自定义…”、托管固定模型、权限状态和录音状态需分别本地化。

预计调整：

- `ios/TodoNative/Services/NotificationService.swift`
- `ios/TodoNative/TodoNativeApp.swift`
- `ios/TodoNative/ViewModels/TodoViewModel.swift`
- `ios/TodoNative/Views/SettingsView.swift`
- `ios/TodoNative/Services/OpenAIService.swift`
- `ios/TodoNative/ViewModels/AIViewModel.swift`
- `ios/TodoNative/Services/CompanionVoiceRecorder.swift`
- `ios/TodoNative/Views/CompanionView.swift`
- `ios/TodoNative/Views/DashboardView.swift`
- `ios/TodoNative/Views/MainTabView.swift`
- `ios/TodoNative/Theme.swift`
- `ios/TodoNative/Localization/Localization.swift`
- 对应 `ios/TodoNativeTests/` 测试文件

边界：

- `NotificationService` 是通知开关、授权、标识、调度和取消的唯一入口。
- `OpenAIService` 负责服务商/模型配置解析与迁移，Settings 不直接拼接配置。
- `CompanionVoiceRecorder` 负责权限和录音状态机，CompanionView 只负责展示模式与提交最终 transcript。
- Motion token 位于主题层，业务 ViewModel 不持有视觉动画参数。

## 9. 测试与验证

### 9.1 自动化测试

通知：

- 首次状态迁移与 App 开关持久化。
- 系统允许、未决定、拒绝和受限下的开启结果。
- 关闭后取消任务提醒并阻止新调度。
- 重新开启只恢复未来、未完成、未归档任务。
- 新旧通知标识兼容清理。
- Debug 待发数量只统计任务提醒。

AI 配置：

- 每个服务商预设列表和默认项正确。
- 服务商切换后恢复各自选择和自定义值。
- 自定义模型/Base URL 的空值校验。
- 旧全局配置只迁移一次。
- 托管路径固定使用 `deepseek-v4-flash`；直连路径使用当前服务商有效配置。

语音：

- 完整状态机与权限失败分支。
- 最终 transcript 写入、草稿追加、空结果保持。
- 临时 transcript 不覆盖草稿。
- 切换模式、页面退出和进入后台时清理资源。
- AI 忙碌时禁止开始，但不阻止停止已有录音。

### 9.2 模拟器检查

- 运行 AGENTS.md 指定的 iPhone 17 Pro / iOS 27.0 测试目标。
- 检查中文/英文、浅色、高对比度、常规/大号动态字体、减少动态效果。
- 截图比较首页、设置和伙伴页的关键状态：通知开关开/关、预设/自定义模型、键盘/录音/处理中。

### 9.3 真机复测

1. WiFi 构建、安装并启动 Debug App。
2. 开启提醒，创建未来到期任务，确认待发数量和到时通知。
3. 关闭提醒，确认待发任务提醒清零；再创建任务确认不调度。
4. 重新开启，确认仅未来有效任务恢复。
5. 验证 Debug 测试通知；另用 Release 配置确认诊断行不存在。
6. 切换多个服务商、预设模型和自定义模型，重启后检查持久化。
7. 伙伴页验证键盘/语音图标切换、点击开始/结束、草稿追加、权限拒绝与后台中断。

## 10. 实施分组

后续实施计划按四个可独立验证的主题组织：

1. 通知总开关、授权门控、调度恢复与 Debug 诊断隔离。
2. 服务商常用模型、自定义模型和配置迁移。
3. 伙伴键盘/语音模式、录音状态机与权限处理。
4. 今日页层级、统一 Motion token、Reduce Motion 与视觉验收。

各主题先补测试，再实现，再进行整体构建和真机验证。提交也按少量逻辑主题整理，不提交 `.superpowers/` 头脑风暴临时文件。

## 11. 本轮不做

- 不扩展 Cloudflare Worker 为多模型代理；只允许把已停用的固定模型迁移为当前固定模型。
- 不重做 Web 端页面或交互。
- 不增加账户系统、云同步或新的订阅产品。
- 不引入第三方 UI/动画框架，也不复制微信资源。
- 不解除项目当前的 Light Mode 限制；深色主题作为后续独立设计任务。
- 不改变自然语言到期解析规则、通知正文或任务数据模型含义。
- 不把测试通知放入 App Store/Release 用户界面。
