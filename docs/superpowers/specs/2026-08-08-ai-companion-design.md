# AI 情绪价值伙伴（AI Companion）设计

日期：2026-08-08
状态：已确认（Phase A 范围）

## 背景

AI Native To Do 已解决目标拆解（智能拆解/复盘/今日计划，web + iOS 双端），但缺乏动机与情感支持。目标是让 App 从冷冰冰的 to-do list 变成真正的 AI companion——像电影《Her》中的 Samantha：温柔、有洞察、记得你。

## 需求决策（已与用户确认）

- **核心形态**：对话式伙伴为主入口 + 任务卡小脚印（完成庆祝/拖延关心），先对话后嵌入
- **人格定位**：温柔知己（Samantha 风：柔 / 懂 / 暖）
- **记忆**：跨会话记忆（摘要滚动合并 + 里程碑事件）
- **主动性**：进门问候 + 关键时刻主动（in-app，无推送）
- **入口**：独立伙伴窗（web 集成右侧 detail 面板 Tab；iOS 新增伙伴 Tab）
- **能力边界**：默认「只读 + 建议，写需确认」；设置提供「直接读写」开关（Phase B 生效）
- **实现路径**：Phase A（对话伙伴层）→ Phase B（Function Calling 真 Agent，本次只留扩展点）

## 架构

纯前端架构（web 无后端、iOS 本地 SwiftData、LLM 直连多厂商），与现有 AI 功能（OpenAIService / app.js callOpenAI）同构。

### Phase A：对话伙伴层

核心组件：

1. **CompanionCore**（web / iOS 同构逻辑）
   - 人格：温柔知己，系统提示词包含伙伴名字、语气、称呼
   - 上下文打包器：组装每次请求的 prompt
   - 对话循环：用户消息 → 打包 → callOpenAI → 响应 → 渲染 + 建议动作 + 摘要

2. **关键时刻引擎**（本地规则，双端同构）
   - 进门：app 打开 / 页面加载 → 问候 + 基于状态的关心或庆祝
   - 完成庆祝：单次完成 ≥1 件 或 同日完成第 3 件 → 真诚具体庆祝
   - 拖延关心：任务创建 >3 天未完成且未关心过 → 不评判地询问
   - 事件以「事实描述」形式进入上下文，由模型自然承接，不生硬提示

3. **记忆系统**
   - 会话结束生成摘要：LLM 摘要指令；失败/无 Key 用本地规则摘取
   - 滚动合并：`新摘要 = 旧摘要 + 本会话事件`，控制 token
   - 里程碑事件自动 append（不依赖摘要生成）
   - 存储：iOS SwiftData 模型 `CompanionMemory`（date + text + type）；web localStorage key `companion_memory`

4. **权限**：默认「只读 + 建议，写需确认」
   - 伙伴输出建议动作卡片（如「要不要加入待办？」），用户点确认才写入
   - 复用现有 handleBreakdown / captureNaturalLanguage 写入逻辑
   - 设置页「直接读写」开关（Phase A 标记即将到来）

### Phase B：真 Agent（后续阶段，本次只留扩展点）

- 同一对话层 + function calling 工具注册（任务 CRUD）
- Phase A 的建议动作对象 = Phase B tool-call 的 UI 呈现形态，天然升级

## 数据流

```
用户消息
  → 上下文打包器（人格 + 记忆摘要 + 任务快照 + 最近关键事件 + 最近 8 轮历史）
  → callOpenAI（复用现有多厂商）
  → 响应
  → 渲染（消息气泡 + 建议动作按钮）
  → 会话结束 → 摘要生成 → 写回记忆存储
```

降级：无 Key / LLM 失败 → 本地情感模板（懂状态但不个性化）。

## 上下文快照（每次请求组装）

1. 人格系统提示词
2. 记忆摘要（1-2 段）
3. 任务快照：未完成 Top 8 + 最近完成 3 条 + 今日健康分 + 今日进度
4. 最近关键时刻事件（2 条内）
5. 最近 8 轮对话历史

## 关键时刻引擎规则表

| 触发 | 条件 | 开口方向 |
|---|---|---|
| 进门 | app 打开 / 页面加载 | 问候 + 基于状态的关心或庆祝 |
| 完成庆祝 | 单次完成 ≥1 或同日完成第 3 件 | 真诚具体的庆祝 |
| 拖延关心 | 任务创建 >3 天未完成且未说过 | 不评判地询问 |

## UI / 交互

**伙伴窗**
- web：右侧 detail 面板新增顶部 Tab「伙伴 / AI 工具」；伙伴 Tab = 聊天界面（消息气泡 + 输入框 + 伙伴头像/名字）
- iOS：MainTabView 新增伙伴 Tab；保留拆解/复盘/今日计划为 ActionChips（发送预置 prompt）

**消息形态**
- 伙伴消息支持建议动作按钮（Phase A：新建任务 / 标记完成 / 拆解，用户确认后走现有写入逻辑）
- 任务卡小脚印：完成时卡片出现伙伴短句（可选，连接伙伴窗）

**语言**：跟随当前语言（zh/en），称呼「你」

**设置**：伙伴区——名字（默认可改）、主动问候开关、直接读写开关（即将到来）

**i18n**：新增 `buddy.*` 键

## 错误处理

- 伙伴消息失败：UI 显示「（伙伴暂时沉默）」+ 重试；上下文保持不丢
- 长上下文：超 8 轮裁旧；token 超限只保留摘要 + 任务快照
- 记忆损坏：decode 失败 → 清空重来，不崩溃

## 测试

- 关键时刻引擎：规则表（各触发 / 不重复触发）
- 上下文打包：快照格式、轮数裁剪、摘要合并
- 建议动作：LLM 输出 → 确认按钮映射（web node 测 / iOS XCTest）
- i18n：buddy.* zh/en 全覆盖

## 实施顺序

1. 记忆存储（SwiftData 模型 + localStorage + 摘要机制）
2. 上下文打包器（跨端同构）
3. 对话 UI（web 伙伴 Tab + iOS 伙伴 Tab）
4. 关键时刻引擎
5. 建议动作 + 确认流
6. 设置项 + i18n
7. 测试（iOS XCTest / web node test）

## 边界

- 无推送（Phase 后续再议）
- Phase A 不做 function calling、不做真实「直接读写」（开关 UI 先行）
